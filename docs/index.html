How it works

Release mirrors

Development happens in a private tree. Every tagged release is exported to GitHub through an automated gate that checks the tree for anything that should not be public. Pull requests are reviewed on GitHub, applied to the development tree and ship in the next tag, with your name in the release notes.

Same shape everywhere

Every repository has the same README layout, the same badge row, an issue chooser, a security policy and a support page. Learn one, know them all.

Your data stays yours

Each README says where your data lives. No telemetry, no accounts, no hosted service. Screenshots come from isolated demonstration profiles; nothing personal is in them.

Forks stay honest

BitAgent and XNote keep their upstream licences, notices and authors, and each README says exactly what is upstream's and what is new.

Support

Bugs and ideas

Each repository's issue chooser and Discussions. There is no e-mail address; that is deliberate.

Security

GitHub private vulnerability reporting on the repository concerned, acknowledged within a week. Never a public issue.

Keep it going

If one of these saves you time, you can support the development.
